# RunPilot

RunPilot 是作者为方便自己监控长时间的深度学习训练任务而写的开源技能，没有商业用途。它也能接管普通 Python 脚本：只需提供脚本路径，RunPilot 会读取任务并处理后续步骤。

它既包括指导 Agent 接管、巡查和汇报的技能，也包括执行单次采集与状态管理的固定 Python 程序。**Agent 的汇报能力不等于固定程序自动具备同样能力。**

## 能做什么

- **接管 Python 任务**：给出脚本路径，识别运行环境和已有进程。
- **按原配置运行**：经授权和安全检查后，按原命令启动；不为提高利用率擅改科研设置。
- **主动发现并行机会**：有显著资源余量时主动评估、提示；是否增加并发及上限由用户决定。
- **默认每 20 分钟巡查**：查看进程、进度、资源、阶段结果与完成证据；实际定时覆盖需要已获准并核实的调用入口。
- **主要汇报什么**：巡查简报说明谁在查、查哪台机器、已经得到什么结果、预计何时结束，以及哪些仍未知。

## 巡查与汇报规则

| 问题 | 本版规则 |
| --- | --- |
| GPU 显存有余量，却没有主动提示并行 | 首次识别资源、取得正式运行观测后及后续资源/阶段变化时主动评估；明确给出可申请并行、尚缺证据或需另行改造的结论 |
| SSH 巡查看不出是谁发起 | 每轮会话内 SSH 巡查前说明 Agent 身份与目标，巡查记录及简报保留调用者、采集链路和观测时间 |
| 简报只有“正常运行”，看不到已获结果 | 每份简报都包含阶段结果；有指标就附范围和来源，没有则说明尚无结果、未产生新结果或本轮无法读取 |
| 默认 20 分钟被擅自调整 | 用户没有明确指定其他间隔时沿用 20 分钟，不因预计运行很久或节约 token 自行改频率，也不反复要求确认默认值 |
| 部分回答漏掉预计结束时间 | 接管摘要、巡查简报和进度答复都保留 ETA 项：给出日期、时区、剩余时长、估算范围与依据；不能估算时写明原因 |

### 有显存余量，就应主动提示；但不等于自动开并行

例如一张 32 GiB 级显卡，正式运行时只用了约 6–8 GiB，RunPilot 应主动指出**值得评估并行**，而不是保持沉默直到用户提问。评估还要检查：

- 是否有已批准范围内、可独立运行的 Seed/Fold 或其他单元，是否受项目顺序门禁限制。
- 结果、日志、缓存和共享汇总是否隔离或有可靠锁保护。
- 逐卡显存峰值、后续增长、保留余量，以及 CPU、内存、磁盘是否足够。
- 同类阶段的总体吞吐是否可能受益；没有实测时明确收益尚未验证。

结论应是可操作的：“可申请增加到指定并发上限”“尚缺哪些证据”或“需要另行批准代码/调度改造”。**发现机会与批准执行分开**：未经用户选择保持串行；需要改代码、重启任务或新建运行批次时另行授权，不绕过项目门禁。

### 每份巡查简报包含什么

下面是**格式示例，数值与路径均为虚构，不是当前任务实况**：

```text
RunPilot 巡查｜2026-10-18 23:20（Asia/Shanghai）
巡查者：Codex Agent（当前会话；由已获准的 heartbeat 唤醒）
采集链路：本机 Agent → 已授权 SSH → train-host；非 RunPilot 内置 SSH 采集
任务：run-demo，3 个 seed 均运行中；合计 162/270 单元，较上轮 +9
已获结果：seed42/fold0 的 validation accuracy=0.87，
          来源 outputs/run-demo/seed42/fold0/summary.json（23:18 核对）；
          仅该折中间结果，不是三 seed 最终汇总
资源与并行：GPU 22/32 GiB，当前 3 路；暂不建议继续增加并发
预计结束：训练约 2026-10-19 03:20（还需约 4 小时，低置信度）；
          依据近 20 分钟每 seed 完成 3 个同类单元，余下各 36 个；
          报告生成耗时未知，完整流程结束时间暂不能可靠估算
下一步：维持已授权的 20 分钟巡查，核对剩余单元及最终报告
```

结果项不是只报进度或退出码：对已完成部分，读取项目**已经生成**的 JSON、CSV 或日志中的必要指标，注明任务归属、覆盖范围和新鲜度；不为了巡查新跑评估或改统计口径。没有新结果时可简写“结果未变，沿用上轮已核验指标及其时间”；尚无可验证结果或读取失败时如实说明。

ETA 区分**当前阶段、训练结束、包含报告的完整流程**。阶段切换、并发变化或长时间失联后重新估计；并行分支不能直接相加，也不能用某个 epoch 的 ETA 冒充全任务 ETA。未知项照样保留，不省略、不编造。

每轮保留完整巡查记录；会话内实际执行 SSH 巡查时先表明身份，随后按以上字段简报。跨渠道通知遵守用户已选的事件/频率与静默偏好，不因报告字段变完整就额外推送。

## 快速开始

下面是对话示例：在 Codex 中显式选择技能时，用 `$run-pilot` 代替示意称呼 `/RunPilot`。

```text
/RunPilot
接管 ./example.py 任务
```

RunPilot 会先识别脚本和已有进程：已运行则只读接管；没有运行、且未限定只读时，在授权与安全条件满足后启动。需要补充时只询问阻断动作的具体缺项，不要求用户手填整份技术契约。

默认巡查间隔是 **20 分钟**，无需在每次请求中重申。若用户已明确选择其他间隔，则保留该选择；未建立实际周期入口时，只能承诺单次检查，不能把默认值写成已经启用的后台覆盖。

## 谁在巡查？消耗 token 吗？

| 模式 | 调用者与能力 | token 与边界 |
| --- | --- | --- |
| Agent 定时巡查 | 已获准的 Codex/Agent heartbeat 唤醒 Agent，调用可用工具采集，并按技能整理阶段结果和 ETA | 每次模型唤醒都会消耗 token，静默回复也一样；创建周期入口需要授权 |
| 固定程序 + 已有系统定时器 | 已核实的定时器直接调用 `monitor.py check-once`，保存状态、事件并处理已配置通知 | 固定程序自身不调用模型；不自动唤醒 Agent，也不自动撰写业务结果简报 |
| 手动单次检查 | 用户或 Agent 发起一次检查 | 无已核实的周期入口，就没有持续后台覆盖 |

本版**不自动安装系统定时器或模型 runner**；“建议 20 分钟”与“实际已有每 20 分钟调用”是两回事。仅固定程序中的 `model_submissions=0` 不能证明整个 Agent 工作流零 token。

## 本机与 SSH 的能力边界

- **本机**：固定程序支持 Linux/macOS 上的 Python 任务启动、只读接管、单次巡检和状态/通知管理。
- **目标机运行**：已通过 SSH 登录服务器后，可在目标机安装并运行 RunPilot，将目标机视作 `local`。
- **Agent 通过 SSH 巡查**：Agent 可在用户已授权的连接与工具范围内采集，必须如实标注 Agent 身份和链路；这是外部 Agent 工作流，**不是 RunPilot 内置 SSH 适配器**。
- **尚未实现**：固定程序主动 SSH 采集/远程启动、自动 retry/resume、调度器自动安装、任意项目验证器和自动模型分析。固定程序的 SSH 目标仍返回 `unsupported`。

真实 GPU/跨卡并发尚未由仓库测试验证；不能把某次外部 Agent 运行记录当成内置运行时的端到端验证。缺少退出回执不等于失败，进程结束或退出 0 也不自动等于业务报告完整。

## 安装与更新

安装技能：

```sh
npx skills add https://github.com/OoooP0731/RunPilot --skill run-pilot
```

更新已安装的技能：`npx skills update run-pilot`（按提示选择原安装范围，并核对安装目录中 `SKILL.md` 的 `metadata.version`）。有活动任务时，先保留原运行时、私有状态和监控入口；不把更新技能当成重启任务的授权。

版本变更见 [CHANGELOG.md](CHANGELOG.md)，实际验证范围见 [TESTING.md](TESTING.md)。

## 给编码 Agent 的接入 Prompt（开发接口）

普通脚本不必为了接管而改代码；RunPilot 可以读取已有日志，也能仅观察进程。**新项目或明确批准的接口改造**可将下面这段 Prompt 交给编码 Agent。它用于编写项目的可观测接口，不是安装技能后的巡查指令，也不授权启动、重跑任务或安装后台服务：

```text
请为当前 Python 项目提供与 RunPilot 兼容的可观测接口。

先读取项目现有入口、日志、进度、结果文件及测试，提交最小改动方案；
已有接口能满足要求时直接复用，不引入第二套状态或重写训练逻辑。

1. 保留原命令、科研参数、随机种子、数据划分、精度和成功定义。
   不为了监控修改 Batch、epoch、world size 或实验范围。
2. 复用或按已批准方案写出普通 JSON 进度文件：
   step/total 表示当前同类阶段，phase 表示阶段，label 区分 Seed/Fold。
   不知道总量时不编造；用同目录临时文件和原子替换，避免读到半份 JSON。
3. 最终结果沿用项目原有指标及完整性约束；只有原定工作和必需产物全部通过
   才写成功状态。阶段指标与最终汇总分开，不用退出 0 掩盖不完整报告。
   有真实 run/unit/attempt 标识时保留归属，不伪造 RunPilot 的私有标识。
4. 若已有独立单元入口，说明精确 argv、依赖、输出/日志/缓存/共享汇总路径
   及锁的作用域；没有则明确当前不能安全并行，不自行增加 Seed/Fold。
5. 项目代码不安装定时器、不调用模型、不保存凭证，不实现自动重试/恢复。
   默认 20 分钟是巡查调用方的规则，不是在训练循环里 sleep 或创建服务。
6. 补充接口测试：JSON 可读、阶段/标签变化、旧结果不能冒充本轮结果、
   报告缺字段/缺分组不能通过。验证不得启动正式训练或改写已有结果。

交付：最小 diff、测试结果、原入口和写入路径、可供 RunPilot 使用的
progress/completion 字段映射，以及未验证的并行条件。
实现前核对本仓库 run-pilot/references/contract.md 的当前 schema；
遇到不支持的字段或能力，报告缺口，不发明 CLI 参数或承诺内置 SSH。
```

### JSON 接口示例

以下为**虚构的单元级示例**，不是新建实验或修改既有评价口径的要求。项目可沿用自己的字段名，由声明式映射适配。

进度文件 `/absolute/project/progress.json`：

```json
{
  "phase": "train",
  "label": "seed42/fold0",
  "step": 8,
  "total": 50
}
```

结果文件 `/absolute/project/report.json`：

```json
{
  "status": "completed",
  "accuracy": 0.88
}
```

对应运行契约中 `units[]` 某个单元的**字段片段**如下，不是可直接初始化的完整契约。路径和字段必须按真实项目调整；完整契约由 Agent 在用户私有状态目录中生成，不要求用户手填：

```json
{
  "progress": {
    "kind": "json",
    "path": "/absolute/project/progress.json",
    "step_field": "step",
    "total_field": "total",
    "phase_field": "phase",
    "label_field": "label",
    "work_kind": "epoch"
  },
  "completion": {
    "kind": "json",
    "path": "/absolute/project/report.json",
    "required_fields": ["status", "accuracy"],
    "success_field": "status",
    "success_value": "completed"
  }
}
```

进度不参与完成验收；上述结果只表示该示例单元的项目定义，不自动证明其他 Seed/Fold 或最终报告完成。原项目有分组/产物约束时，必须映射既定非空分组和必需字段，不能删约束照搬简例。仅对原本约定“退出 0 即完成”的新受管脚本，才可选择 `completion.kind=exit_code`；只读接管不凭 PID 消失推断成功。

完整字段与归属规则见 [运行契约](run-pilot/references/contract.md)，固定程序命令及报告要求见 [操作说明](run-pilot/references/operations.md)，实际技能入口见 [SKILL.md](run-pilot/SKILL.md)。README 提供接入说明，不维护第二份完整技能 Prompt。

## 仓库结构与开发

| 路径 | 用途 |
| --- | --- |
| `run-pilot/` | 可安装技能：入口、按需参考、固定运行时脚本及离线验收场景 |
| `tests/` | 运行时与文档接口的自动化回归测试 |
| `tools/` | 技能源校验、打包和临时 CPU 闭环验证 |
| `dist/` | 与发布源码一致的 `run-pilot.skill` 和 SHA-256 校验文件 |
| `example.py` | 不依赖 GPU/PyTorch 的最小 Python 示例，文件名不绑定版本 |
| `CHANGELOG.md` / `TESTING.md` | 版本变更历史 / 当前验证范围 |

```sh
make test
make validate
python3 tools/verify_local_runtime.py
make build
```

CPU 闭环验证只运行临时合成任务并清理临时文件，不接管真实训练。`main` 保留当前代码、文档和必要工具；历史规划与旧 Prompt 从当前目录移除，仍可在 Git 历史和旧 tag 中查阅。版本信息由技能元数据、运行时版本常量、CHANGELOG 和发布 tag 管理，不给通用文件名添加版本后缀。
